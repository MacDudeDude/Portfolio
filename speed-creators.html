Unity / 2025 - 2026 / Steam

"Speed Creators is an online multiplayer platformer where all players build a level, the game stiches each level together, and everyone races through it all at once"
About

The general idea actually came from a game jam, but not mine. I was playing a random submission that had a built in level editor. But it was just an editable image where colors corresponded to specific objects when you loaded it. It gave me the idea for a .io style game where you could quickly draw a level and make your friends race through it. I wanted to use Unity so I just scrapped the web idea. And I forgot where the end gameplay concept of seperate levels stiched together came from.

-

I started working on this project in 2022, but work was very infrequent until 2025 where I really began adding and finishing features before the full release. Work was lonely, besides paying someone for original music.

Systems

Networking

I made a custom networking manager that uses Facepunch.Steamworks, allowing for mutliplayer lobbies of up to 200 players. Player data is sent based on a tick system and interpolated between ticks. All traps are synced with a single timer to keep bandwith low.

Custom Level Editor

Since players had to send their levels during the game, I used custom serialization for really small file sizes. This had the added benifit in making downloads and uploads to the steam workshop really fast.

Audio Manager

I faced a problem with audio quickly, lots of traps with varying timing quickly reached the audio playback limit. My solution was an audio manager that essentially keeps track of currently playing audio sources. When it recieves a call to play a sound, it checks if that sound is already playing. If it is, it checks variables such as distance, the audio clip length, and the time left on the currently playing clip. Then it decides whether to ignore the request or play it and stop the old one. The result is tons of traps and a variety of sounds with zero clipping.

Challenges

Networking Bugs

The biggest challenge I had when creating this game was the networking, especially fixing the bugs that only happened in rare situations. Using just steamworks to handle connections meant I couldn't test it from a single computer. Being forced to test every change with two computers was quite a slog.

-

To aid in this process I tried to make the networked code as clear as possible, making it easier to determine where the source of a bug would be. And any explicit errors would be exposed in game so I could see the exact error log. Overall though, I think things could have been easier had I used an out of the box networking solution/manager instead. But I will say, managing packets is very fun.

Refactoring

As mentioned earlier, a good chunk of the code and systems were done in 2022, back when I was still pretty new to coding in general. So a lot of the systems and overall project structure was, to put it lightly, very bad. I didn't want to spend even more time on this project, so a big challenge was finding a balance between refactoring systems and just finishing.

-

What helped was taking a few days to plan which systems really needed to be rewritten, and which ones could just do with some minor changes. I'm pretty happy with how it turned out, but a part of me still wants to completely rewrite the game from scratch.

Preformance

Since I wanted huge lobbies with potentially over a hundred levels, I needed to keep preformance in mind and it's something I tested many times. Traps are culled and disabled when offscreen, and all projectiles are pooled. Particle effects are emitted using a particle manager. Tiles use a single respective tilemap, set all at once.
